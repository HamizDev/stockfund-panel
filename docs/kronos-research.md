# Kronos 预测研究

「数据与工具 → K线预测」提供四个通用研究入口：

| 入口 | 用途 |
| --- | --- |
| 单次预测 | 自选股票或场内 ETF，按实际交易日历生成日 K 或后续一分钟情景；不会下单 |
| 配置对比 | Base 在同一份冻结行情上比较最多三个历史窗口，避免各组取数时点不同 |
| 成绩汇总 | 对照已形成的真实行情，查看覆盖数、误差、方向一致率和保持原价的基线 |
| 候选模型 | 保存通过完整性核验的候选配置；不会微调权重、自动晋级或替换基线 |

日 K 使用蜡烛图；分钟周期使用分时走势。预测若不满足开高低收关系，只显示有效收盘路径，不修补成看似真实的预测蜡烛。分钟历史不足或原价口径不可核验时不预测。

所有新任务使用 Base。模型更大不等于在每只标的上更准确；方向一致率也不是扣费后的交易胜率。缺报价不计错误，缺少生成时刻或结果晚于首个目标收盘时不计事前成绩。原预测不被核对结果覆盖。

## 可选独立运行环境

仓库只包含适配与执行器，不包含模型权重、第三方模型源码、PyTorch、个人预测或训练资料。没有配置环境时显示「未就绪」，其他看板功能仍可运行。

1. 按 [Kronos 官方项目](https://github.com/shiyu-coder/Kronos) 的说明，在独立目录安装兼容依赖和支持本机 GPU 的 PyTorch。虚拟环境放在该目录的 `.venv/`。
2. 官方模型源码放入 `source/`，使 `source/model/__init__.py` 存在；将本仓库 `scripts/kronos/runner.py` 复制到该目录。
3. Base 和 tokenizer 的模型及配置分别放入 `models/base/`、`models/tokenizer/`。执行器核对固定权重 SHA256；不接受任意替换的模型文件。
4. 在仓库执行 `python scripts/kronos/check_runtime.py --runtime <独立目录> --write-ready`。检查成功后才写就绪标记，不下载模型、不训练、不生成预测。
5. 启动后端前设置环境变量 `KRONOS_RUNTIME_DIR` 为该独立目录；未设置时使用 `DATA_DIR/kronos-runtime`，也支持项目默认 `data/kronos-runtime`。重启后端后在页面刷新状态。

当前执行器需要 CUDA。CPU-only 环境显示未就绪或检查失败；不要手动创建空的 `ready.json` 绕过环境核验。

GPU 任务串行执行，可取消，独立执行进程结束后释放 GPU 上下文。后台仅核对真实行情并保存独立成绩，不调用 AI、不改变模型权重。记录数量和文件大小有上限；达到上限时保留原件并拒绝继续写入。

公开版不包含个人固定标的池、自动训练/历史交易计划或已开启的自动预测计划；不会连接交易所执行买卖。候选配置仍使用原始 Base 权重，不表示已经训练出更优模型。
